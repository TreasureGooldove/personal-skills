# 项目创建前的技能更新检查

在每次创建新项目之前，先执行一次更新检查，再继续项目创建。同一个项目创建流程内不重复检查；已有项目的普通修改不触发。

## 执行

1. 使用本技能目录下的脚本，按实际路径运行，不依赖当前工作目录：

       python "<本技能目录>/scripts/check_updates.py"

   需要 Python 3、Git 和已登录的 GitHub CLI（gh）；私有集合仓库需要访问权限。
   已知当前安装集合的提交时，追加 --collection-base <提交SHA>。
   在集合源码仓库中运行会自动识别本地提交；安装缓存没有基线时明确报告“本地版本未知”。

2. 检查 personal-skills 集合远端以及 references/upstream-lock.json 记录的四个上游。
   上游比较以当前打包提交为基线，不代表每个上游提交都会影响本技能。
   同步上游版本时，同时更新仓库根目录和本技能 references/ 内的锁文件。

3. 简要向用户展示：哪些仓库有更新、新增提交数量、主要变化和比较链接。
   提交标题只能作为摘要线索；涉及破坏性变更或具体行为结论时，阅读相关 diff 或发布说明后再概括。
   默认控制在 3–6 行，细节有需要再展开；不要把提交标题摘录当作完整变更日志。

4. 无更新就说明“技能仓库及上游已检查，无更新”。
   仅在全部项目均成功检查且为 current/identical 时使用这句话。
   缺少基线、网络失败、权限不足或历史分叉时，明确指出未确认的项目，不能称为“已是最新”。
   检查失败不应无限重试或阻塞无关的项目创建；简要说明后继续可进行的工作。

5. 该步骤只检查和展示更新，不自动覆盖技能、修改锁文件或改变现有项目依赖。
   需要升级时依据用户授权完成同步、兼容性验证、版本记录和中文 Git 提交。

## 输出示例

技能更新检查：
- personal-skills：已是最新。
- UI/UX Pro Max：新增 2 个提交，涉及配色数据修正（附比较链接）。
- 其余上游：无更新。

示例不代表实际检查结果，必须以本次执行输出为准。
